# 시범 구성과 동작 순서 비교

## 실험 목적

시범의 양, 동작 순서와 수집 구성에 따라 Toy2Box 정책 성능이 어떻게 달라지는지 비교한다. 조작자 수의 영향을 연구하려면 한 명과 여러 명의 데이터를 같은 조건으로 비교해야 한다. 현재 `multi_operator_100`은 서로 다른 시범 파일 5개를 합친 실험 이름이며, 파일 수만으로 서로 다른 사람 5명의 시범이라고 판단하지 않는다.

이 문서의 수치는 2026-11-01에 확인한 로컬 파일·학습 로그·영상에서 가져왔다.

## 데이터와 학습 구성

| 실험 ID | 원본 시범 | annotation | 학습 시범 | 평균 원본 시간 | 원본 idle 평균 |
|---|---:|---:|---:|---:|---:|
| `baseline_n100` | 100 | 99 | 500 | 14.61초 | 0.70% |
| `new_rule_20` | 20 | 19 | 1,000 | 32.81초 | 20.23% |
| `new_rule_100` | 100 | 98 | 1,000 | 32.20초 | 20.08% |
| `multi_operator_100` | 100 | 93 | 1,000 | 34.16초 | 27.41% |
| `xy_first_20` | 20 | 20 | 1,000 | 35.63초 | 20.33% |

원본 시범 수, annotation 출력에 남은 시범 수, Mimic으로 생성한 학습 시범 수를 구분한다. annotation 감소의 구체적인 이유는 개수만으로 단정하지 않는다. idle은 각 episode에서 이동·회전 action 6개가 모두 정확히 0인 프레임의 비율을 구한 뒤 episode 간 평균한 값이다. 시간은 제어 간격 0.05초로 계산했다.

모든 실험의 학습 seed는 101이고 checkpoint는 epoch 2000이다. BC-RNN은 LSTM hidden 400, 2 layers, GMM 5 modes, sequence length 10이다. 각 실험은 학습 모델 1개 기준으로, seed 2개 평균 결과가 아니다.

`new_rule_20`과 `new_rule_100`은 같은 Mimic 파일 경로를 사용했다. 현재 파일은 100개 원본 기반 생성물이다. 20개 원본 실험은 당시 학습 로그의 1,000개 시범 기록과 보존된 모델/config로 식별하며, 현재 HDF5 해시를 당시 학습 입력의 해시로 사용하지 않는다.

## 동작 규칙

`new rule`의 공통 순서는 다음과 같다.

1. 회전으로 수직 파지 자세를 맞춘다.
2. XY 이동으로 트럭 위에 접근한다.
3. 수직 하강 후 그립한다.
4. 물체를 박스보다 충분히 높게 들어 올린다.
5. 박스 입구로 이동하고 정렬한 뒤 릴리즈한다.

속도 변화와 분산 정지를 포함하며 목표 idle은 21%다. `xy_first_20`은 앞부분을 XY 이동 → 회전 → 수직 하강으로 바꾼 실험이다. 수집기에서 확인한 성공과 학습 정책의 성공률은 별도 지표다. 구현 및 다른 접근 순서의 상태는 [동작 규칙](collection_rules.md)에 정리했다.

## new rule과 multi operator 비교

평가 명령 이력은 task 동일, seed 42, 100회, horizon 800이다. 저장된 정책 영상의 프레임 수를 확인했다.

| 실험/실행 | 영상 수 | 800프레임 미만 | 800프레임 | 정확한 정책 성공률 |
|---|---:|---:|---:|---|
| `new_rule_20` | 100 | 56 | 44 | 결과 로그 미확보 |
| `new_rule_20` 재실행 | 100 | 56 | 44 | 결과 로그 미확보 |
| `new_rule_100` | 100 | 68 | 32 | 결과 로그 미확보 |
| `multi_operator_100` | 100 | 32 | 68 | 결과 로그 미확보 |

56·68·32는 영상 개수이며 성공 횟수가 아니다. 조기 종료에는 실패가 포함될 수 있고, 영상만으로 성공 판정 당시 상태를 복원할 수 없다. 따라서 이 값으로 성공률이나 통계적 유의성을 계산하지 않는다. 재실행은 같은 모델의 반복이며 독립적인 학습 seed 실험으로 세지 않는다.

동작 순서의 일관성이 학습을 도왔을 가능성을 검토하고 있다. 다만 여러 원본 파일에는 동작 순서·정지 시간·접근 경로 등의 차이도 들어가므로 조작자 수 하나의 효과로 해석할 수 없다. 정책의 정확한 성공률과 우열은 [결과 저장 도구](evaluation.md)로 재평가해 확인한다.

## new rule과 기존 n100 비교

`baseline_n100`은 원본 100개 → 학습 500개, `new_rule_20`은 원본 20개 → 학습 1,000개다. 원본 개수와 Mimic 개수가 함께 달라 동작 규칙만의 효과를 분리할 수 없다.

`new_rule_100`은 원본 수를 100개로 맞췄지만 Mimic 개수는 여전히 기존 n100의 두 배다. 규칙의 효과를 비교하려면 Mimic 개수까지 같게 맞춰야 한다.

기존 `videos/agibot_bc_mimic` 폴더는 다른 checkpoint 평가에도 사용된 기록이 있다. 해당 폴더의 조기 종료 영상 24개를 n100의 성공 횟수나 결과로 연결하지 않는다. 기존 n100도 고유한 출력 폴더와 checkpoint 해시를 남기며 다시 평가해야 한다.

## 저장 시범의 재생 검증

| 원본 | action 재생 수 | 성공 조건 10 step 연속 충족 |
|---|---:|---:|
| `new_rule_20` | 20 | 20 |
| `new_rule_100` | 100 | 100 |
| `multi_operator_100` | 100 | 91 |
| `xy_first_20` | 20 | 20 |

이 표는 초기 상태를 복원한 뒤 저장 action을 그대로 재생한 결과다. 학습된 정책이 새로운 관측을 보고 결정한 평가 결과와 다르다. 혼합 원본 중 재생 성공 조건을 충족하지 않은 9개는 별도 확인 대상이다. 이 9개와 annotation에서 빠진 7개가 같은 시범이라고 단정하지 않는다.

## 다음 비교에서 맞출 조건

- 한 명과 여러 명의 실제 수집자 정보를 확인하고 기록한다.
- 두 조건의 원본 수를 100개로 맞추고 같은 파지·이동 순서를 사용한다.
- Mimic 학습 시범 수와 생성 설정, 학습 구조·epoch·seed를 맞춘다.
- 같은 평가 seed와 horizon에서 성공 여부를 rollout별로 저장한다.
- 학습 seed 101·111을 각각 평가하고 접근·파지·운반·배치 실패를 구분한다.

[Release](https://github.com/Kim-KiSuk/Robotics-Simulation-Assignmnet2/releases/tag/experiments-2026-11-01)에 5개 실험의 수집 원본 HDF5와 rollout에 사용한 epoch 2000 모델을 한 쌍씩 제공한다. `new_rule_20`과 vertical은 원본 20개, `new_rule_100`·n100·multi operator는 원본 100개다. annotation·Mimic HDF5와 중간 epoch 가중치는 포함하지 않는다. 기본 선택 모델 `models/final_model.pth`는 `new_rule_100`의 Release 가중치와 같다.
